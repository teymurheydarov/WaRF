=== ONE decision REJECT
[REJECT] **Main defect: the first `getMapper` overload ignores the `conforming` flag.**
- `getMapper(bool conforming, index_t nComp, gsDofMapper& mapper, bool finalize)` removed the `if (conforming) { ... matchInterface(*it, mapper); }` block.
- It now calls `gsDofMapper(*this, this->topology(), nComp)` and never reads `conforming`.
- The result is the same whatever the caller passes:
  - If that constructor matches interfaces, callers asking for `conforming == false` (discontinuous or non-matching patches) silently get glued interface DOFs.
  - If it does not, callers asking for `conforming == true` silently get unglued DOFs.
- Either way the DOF count and numbering are wrong, so assembly and transfer operators break with no error raised.
- The second overload does forward `conforming` (`gsDofMapper(*this, bc, nComp, unk, conforming)`). This shows the flag is still meant to matter, and that the first overload simply dropped it.

**Secondary issues:**
- **Signature change:** both `getMapper` overloads gained an `nComp` parameter in the middle of the argument list, and `unk` changed from `int` to `index_t`. The header change is not in the diff, so existing callers, such as `uniformRefine_withTransfer` and other `getMapper` overloads, may no longer compile. Worse, an `int` argument could bind to `nComp` and shift every later argument.
- **Swapped assertion messages:** in `combineTransferMatrices`, the message for the `cols()` check talks about rows, and the message for the `rows()` check talks about columns. This misleads debugging but does not change behaviour.
- **Unchecked size assumption:** the new multi-component loop assumes `localTransferMatrices[j]` has the same size for every component. That holds only if all components share one basis per patch. This is acceptable but should be documented.

Ignoring the `conforming` argument is a real behaviour regression, so the patch should not be merged as is.

The first `getMapper(bool conforming, index_t nComp, gsDofMapper&, bool finalize)` overload now ignores its `conforming` argument.

**Before the patch**, interfaces were matched only on request:
```cpp
mapper = gsDofMapper(*this);
```

**After the patch**, the body is:

- If it always glues, a caller asking for a non-conforming mapper (`conforming=false`) gets merged interface DOFs. This silently couples patches that should be independent.
- If it never glues, `conforming=true` callers lose interface continuity.

The sibling overload in the same patch shows this isn't intended. It forwards the flag explicitly: `gsDofMapper(*this, bc, nComp, unk, conforming)`. The first overload has no equivalent, so it looks like the flag was dropped during the refactor rather than deliberately encoded in the constructor.

The old code matched interface DOFs only when `conforming == true`. The new code passes the full topology to the `gsDofMapper` constructor every time, and that constructor matches interfaces itself. `conforming` is never read.

As a result, a caller asking for a non-conforming mapper (`conforming == false`) silently gets interface DOFs merged. That changes the DOF count and couples patches that should stay independent, for example in DG or mortar discretizations. Nothing fails at compile or run time; the results are just wrong.

The second overload does pass `conforming` through (`gsDofMapper(*this, bc, nComp, unk, conforming)`). So the two overloads now handle the same flag differently, which also suggests the first one is an oversight rather than a deliberate change.

**Secondary concerns (not blocking on their own)**

1. **Swapped assertion messages.** In `combineTransferMatrices`, the check against `localTransferMatrices[j].cols()` says "number of rows", and the check against `.rows()` says "number of columns". The checks are correct, but the messages will mislead anyone debugging a failure.
2. **Signature change for existing callers.** The second overload changes from `(bool, bc, int unk, mapper, bool)` to `(bool, bc, index_t nComp, index_t unk, mapper, bool)`. The header and every call site must be updated together. An old call `getMapper(c, bc, unk, mapper)` could silently bind `unk` to `nComp` if implicit conversions allow it. The diff gives no evidence that callers were audited.
3. **`matchInterface` is now unused by `getMapper`.** It is still public and iterates over all components, but nothing in this patch calls it any more. That is worth confirming.

**What looks correct**

The multi-component rewrite of `combineTransferMatrices` is sound:
- Each component's DOFs are mapped through `index(i, patch, comp)`, which is the right argument order.
- Reserving `nonzeros * componentsSize()` entries matches the number of triplets added.
- The new consistency assertions on patch count, component count, and per-patch sizes are useful.

**To fix**

- Restore the `conforming` behaviour in the first overload. Either build the mapper without topology and call `matchInterface` when `conforming` is true, or pass `conforming` to the constructor as the second overload does.
- Correct the two assertion messages.
- Confirm that all call sites of the changed overload have been updated.

**4. Minor issues.**

- `trRows` and `trCols` are computed but never used.
- The signature change inserts `nComp` before `mapper`. Mismatched callers will fail to compile, which is loud. However, if the header gives `nComp` a default value, existing calls like `getMapper(true, mapper)` could bind in unexpected ways.

Item 1 alone is a real defect whose failure is silent.
