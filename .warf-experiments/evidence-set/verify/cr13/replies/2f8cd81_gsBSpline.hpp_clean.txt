=== ONE decision REJECT
[REJECT] 1. **Division by zero in `pseudoCurvature()`.** `len` is the distance between the first and last control points. For any closed curve, such as a circle or a closed loop, those points coincide, so `len == 0`. The function then returns `total / 0`, which is `inf` or `NaN` with no guard. `intersect` relies on `getPotentialIntersectionRanges`, which uses curvature estimates to decide when to stop subdividing. A `NaN` or `inf` there can wrongly prune real intersections or cause unbounded subdivision.

2. **Out-of-bounds read in `pseudoCurvature()`.** If `m_coefs.rows() == 0`, `coefsSize - 1` is `-1`, so `m_coefs.row(-1)` reads outside the matrix. There is no `GISMO_ASSERT` or early return. A curve read from untrusted XML through the `gsXml<gsBSpline<T>>::get` path shown in the context could reach this.

3. **`std::max(1e-10, tolerance)` breaks for non-`double` `T`.** `1e-10` is a `double`, so for `T = float` or `long double`, `std::max` cannot deduce one type and the code fails to compile. The class is templated on `T` and G+Smo instantiates other real types, so this breaks those builds. It should be `std::max((T)1e-10, tolerance)`.

4. **Unchecked convergence in `intersect`.** The result of `obj.compute(uv, tolerance)` is only checked against the distance threshold. Nothing checks that `uv` stayed inside each segment's domain. If the solver drifts, `crv1.eval(uv.row(0))` evaluates outside the segment's parameter range, and the reported parameters are also local to the sub-segment rather than the original curve.

5. **Same-object aliasing in `toBezier`** (context code). `currentSegment.splitAt(*iter, leftPart, currentSegment, tolerance)` passes `currentSegment` as both the object being split and the `right` output. `splitAt` writes `left` first and then calls `segmentFromTo` on `*this` while assigning into `right`, which is the same object. This works only because of the order of operations inside `splitAt`, so it is fragile.

Items 1–3 are concrete defects in the added code, so the patch should not be merged as is.

**`intersect(other, tolerance)`**
- It gets candidate parameter ranges from `getPotentialIntersectionRanges`, which pairs overlapping bounding boxes.
- For each pair, it extracts the sub-curves with `segmentFromTo` using each range's min and max.
- It starts a distance-minimization solve from the midpoints of the two sub-domains. Midpoints are a reasonable initial guess.
- It accepts a result when the remaining distance is below `max(1e-10, tolerance)`, so the threshold never drops to zero.
- The reported point is the average of the two curve evaluations, which is a sensible symmetric choice.
- `uv` is fully set before `compute` is called, so nothing is read uninitialized. `uv.row(0)` and `uv.row(1)` are valid 1×1 parameter blocks for `eval`.

**`pseudoCurvature()`**
- It computes the ratio of control-polygon length to the straight-line distance between the end control points. This is the intended measure of how far the curve deviates from a straight line.
- Indexing stays in bounds: the loop runs `ipt` from 0 to `coefsSize-2` and reads `ipt+1`.
- A B-spline always has at least one coefficient, so `row(0)` and `row(coefsSize-1)` are valid.

**Security**

--- AUDITOR [REJECT]
The patch adds two public methods, `intersect()` and `pseudoCurvature()`. Neither validates its inputs, and `pseudoCurvature()` can read memory out of bounds.

**1. Out-of-bounds read in `pseudoCurvature()` (blocking)**
```cpp
int coefsSize = m_coefs.rows();
T len = (m_coefs.row(0)-m_coefs.row(coefsSize-1)).norm();
```
- If the curve has no control points (a default-constructed `gsBSpline`, or one loaded from malformed XML), `coefsSize` is 0. The code then accesses `m_coefs.row(0)` and `m_coefs.row(-1)`.
- Eigen only checks indices when assertions are enabled. In release builds (`NDEBUG`) this is an unchecked out-of-bounds read, which is undefined behavior.
- There is no `GISMO_ASSERT` or `GISMO_ENSURE` guarding it. Other code in this file guards its preconditions, for example `splitAt` and `isOn`.

**2. Division by zero in `pseudoCurvature()`**
- If the first and last control points coincide, `len` is 0. This happens for any closed curve, such as a circle or periodic spline, and for a single-point curve.
- The function then returns `inf` or `NaN` with no check or documented behavior.
- A caller using this value for thresholds or subdivision decisions could loop forever or make wrong decisions.

**3. Integer narrowing**
- `m_coefs.rows()` returns `index_t`, which may be 64-bit, but the result is stored in an `int`.
- The loop uses `ipt != coefsSize - 1`. If `coefsSize` is ever 0 or negative after truncation, the `!=` condition never terminates correctly and the loop walks past the buffer.
- The codebase convention is `index_t`, and `<` is the safer loop condition.

**4. `intersect()` trusts its inputs**
- The ranges from `getPotentialIntersectionRanges` go straight into `segmentFromTo`. Its iterator arithmetic (`itStart-p`, `itEnd+1`) depends on the ranges lying inside the knot vector.
- Nothing checks that the ranges are non-degenerate or within each curve's domain.
- `std::max(1e-10, tolerance)` mixes `double` with the template type `T`. It will not compile for non-double `T`, and the codebase helper is `math::max`.
- The Newton result `uv` is never checked to lie inside the segment domains before `eval`, so it can report points outside the curves.

**Required changes before approval:**
- In `pseudoCurvature()`, add `GISMO_ENSURE(m_coefs.rows() >= 2, ...)` and handle or document the `len == 0` case.
- Use `index_t` with a `<` loop condition.
- In `intersect()`, validate the hull ranges against each curve's domain, use `math::max`, and clamp or verify `uv` before evaluating.

--- BOUNDARY [REJECT]
The genuine problem is in `pseudoCurvature()`. It divides by `len`, the straight-line distance between the first and last control points, and nothing guards against `len == 0`. Two ordinary inputs reach that case.

**Closed curves**
- **Input:** a closed (clamped, non-periodic) B-spline whose first and last control points coincide, for example `(0,0), (1,0), (1,1), (0,1), (0,0)`.
- **What happens:** `len` is 0 and `total` is 4.
- **Result:** the function returns `+inf`.
- Closed loops are routine B-spline geometry, so callers can expect to hit this. An infinite ratio will distort any comparison, ranking or threshold built on it.

**Degenerate curves**
- **Input:** a degree-0 curve with a single coefficient (`coefsSize == 1`), or any curve whose control points all coincide.
- **What happens:** the loop never adds anything because `ipt != 0` is false straight away, so `total = 0`, and `len = 0`.
- **Result:** the function returns `0/0 = NaN`.
- A NaN does not fail loudly. It silently makes every later `<` or `>` comparison false.

**Empty coefficients**
- With `coefsSize == 0`, `row(-1)` would read out of bounds.
- A valid `gsBSpline` always has at least p+1 ≥ 1 coefficients, so this case is unreachable under the class contract.

**Other boundaries I checked**
- **`toBezier`:** with a single knot span, the loop range `ubegin()+1` to `uend()-1` is empty, so it returns `{*this}`. That is correct.
- **`intersect`:**
  - Empty `hulls` gives an empty result. That is correct.
  - Distance exactly equal to the threshold is rejected, which is a reasonable choice.
  - `uv` is used after `compute` refines it in place, so the parameter values in the result are consistent.
  - `std::max(1e-10, tolerance)` will not compile when `T` is `float`, because `double` and `float` conflict. That is a build failure, not a runtime boundary bug, so I don't count it as the finding.

**Suggested fix:** guard the divisor. For example, return `std::numeric_limits<T>::infinity()` or 1 by a documented convention when `len` is below a small epsilon and `total` is too. Otherwise, document that the function is undefined for closed or degenerate curves and assert on it.

template<class T>
T gsBSpline<T>::pseudoCurvature() const {
  int coefsSize = m_coefs.rows();

  T len = (m_coefs.row(0)-m_coefs.row(coefsSize-1)).norm();
  T total = 0.0;
  for (int ipt = 0; ipt != coefsSize - 1; ++ipt) {
    T dist = (m_coefs.row(ipt) - m_coefs.row(ipt + 1)).norm();
    total += dist;
  }
  return total / len;
}

template<class T>
void gsBSpline<T>::splitAt(T u0, gsBSpline<T>& left,  gsBSpline<T>& right, T tolerance) const
{
  GISMO_ASSERT(domainStart()-tolerance < u0 && u0 < domainEnd()+tolerance,
               "splitting point "<< u0 <<" not in the knot vector");

  left  = segmentFromTo(this->domainStart(), u0, tolerance);
  right = segmentFromTo(u0, this->domainEnd(), tolerance);
}

template<class T>    
bool gsBSpline<T>::isOn(gsMatrix<T> const &u, T tol) const
{
    GISMO_ASSERT( u.cols() == 1, "Expecting single point.");
    gsBSplineSolver<T> slv;
    gsMatrix<T> e;
    
    for ( index_t k = 0; k != u.rows(); ++k)
    {        
        std::vector<T> roots;
        slv.allRoots(*this, roots, k, u(k,0) ) ;

        if( roots.size()!=0 )
        {
            gsAsMatrix<T> xx(roots); 
            this->eval_into( xx, e ); 
            
            //if( math::abs( e(!k,0)-u(!k,0) ) < tol )
            for(index_t j=0; j!=e.cols(); j++)
                if( ( e.col(j)-u ).norm() < tol )
                    return true;
        }
    }
    return false;
}

template<class T>    
bool gsBSpline<T>::isPatchCorner(gsMatrix<T> const &v, T tol) const
{
    return (( v - m_coefs.row(0)       ).squaredNorm() < tol ||
            ( v - m_coefs.bottomRows(1)).squaredNorm() < tol );
}

template<class T>    
void gsBSpline<T>::findCorner(const gsMatrix<T> & v, 
                                             gsVector<index_t,1> & curr,
                                             T tol)
{
    if ((v - m_coefs.row(0)).squaredNorm() < tol)
        curr[0] = 0;
    else if ((v - m_coefs.bottomRows(1)).squaredNorm() < tol)
        curr[0] = m_coefs.rows()-1;
    else
    {
        curr[0] = m_coefs.rows(); // invalidate result
        gsWarn<<"Point "<< v <<" is not an corner of the patch. (Call isPatchCorner() first!).\n";
    }
}


template<class T>    
void gsBSpline<T>::setOriginCorner(gsMatrix<T> const &v)
{
    if ((v - m_coefs.row(0)).squaredNorm() < (T)(1e-3))
        return;
    else if ((v - m_coefs.bottomRows(1)).squaredNorm() < (T)(1e-3))
        this->reverse();
    else
        gsWarn<<"Point "<< v <<" is not an endpoint of the curve.\n";
}

template<class T>    
void gsBSpline<T>::setFurthestCorner(gsMatrix<T> const &v)
{
    if ((v - m_coefs.bottomRows(1)).squaredNorm() < (T)(1e-3))
        return;
    else if ((v - m_coefs.row(0)).squaredNorm() < (T)(1e-3))
        this->reverse();
    else
        gsWarn<<"Point "<< v <<" is not an endpoint of the curve.\n";
}
