--- CLAUDE 30698a20810c REJECT
1. **`mapMesh` now applies the forward map instead of the inverse.** The comment directly above it says `//// NEEDS TO EVALUATE THE INVERSE MAP, NOT m_composition!!`. The old code called `m_composition->invertPoints(point,tmp,1e-6,true)`, which inverts the composition. The patch comments that out and calls `m_composition->eval_into(point,tmp)`, which evaluates the composition forward. Mesh vertices given in basis parameter space will be mapped the wrong way, so any mesh or plot built through this basis ends up in the wrong place. The leftover `gsDebugVar` lines and commented-out `invertPoints(...,1e-2,...)` suggest this was a debugging workaround committed by accident.

That affects active-function detection and integration domains downstream, and the patch gives no reason for the change.

3. **The bounding box from `support(i)` can be wrong.** Inverting only the corner points of the support box and taking their min and max is only correct for monotone, axis-aligned compositions. For a general nonlinear composition, the preimage's extent can lie between the corners, so the returned support can miss parts where the function is non-zero.

4. **The loop index type mismatches.** `for (size_t d=0; d!=this->domainDim(); d++)` compares `size_t` against `short_t`, which triggers a signed/unsigned comparison warning, an error under `-Werror`.

5. **The patch adds noise.** It brings in a dead, commented-out `#ifndef _NDEBUG` block in `_applyBounds`, which also uses the non-standard macro name `_NDEBUG`. It also keeps a commented-out `// return this->support();`. Neither belongs in a merge.

Point 1 alone is enough to block the merge: it reverses the mapping direction that the code's own comment says is required.
