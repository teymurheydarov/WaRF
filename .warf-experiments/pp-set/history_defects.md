# Confirmed PPSSPP defects outside the test set (both judges yes; the first 40 in candidate order)

- Core/PSPLoaders.cpp (2014-02-15): The new loop sets bootpath to EBOOT.OLD whichever alternate boot file exists, and the new PAKFILE2.BIN entry points to SYSDIR instead of USRDIR. | The new loop assigns the constant EBOOT.OLD path instead of altBootNames[i] when any alternate boot file exists (and lists PAKFILE2.BIN under SYSDIR instead of USRDIR), so most patched games boot a nonexistent file.
- Core/MIPS/ARM64/Arm64RegCache.cpp (2015-07-07): In FlushAll the static check for the second register of a pair tests mr[i].isStatic instead of mr[i + 1].isStatic, so a static register holding a pure imm can be stored via SCRATCH2 and then discarded. | FlushAll's added static check for the second register of a pair tests mr[i].isStatic instead of mr[i + 1].isStatic, so a static reg can be paired into a scratch STP (and static ML_IMM regs now used via SetImm keep ML_IMM after being materialized).
- GPU/GLES/GLES_GPU.cpp (2014-06-11): CopyDisplayToOutputInternal now calls SetRenderFrameBuffer, which picks a framebuffer from the current gstate instead of rebinding the last render target, causing the Jeanne d'Arc world map artifact. | CopyDisplayToOutputInternal now calls SetRenderFrameBuffer, which picks or creates a framebuffer from the current gstate at display time instead of rebinding the last render target, causing artifacts (Jeanne d'Arc world map).
- Common/ppcEmitter.h (2013-08-15): SUB(Rd, Ra, Rb) emits SUBF(Rd, Ra, Rb), which computes Rb - Ra, so the operands are reversed. | SUB(Rd, Ra, Rb) emits SUBF(Rd, Ra, Rb), which on PowerPC computes Rb - Ra, so the operands are reversed.
- Core/MIPS/x86/CompLoadStore.cpp (2013-03-08): CompITypeMemRead/Write pass a fixed size of 4 to PrepareRead/PrepareWrite, so memchecks for byte and halfword accesses test a 4-byte range and trip falsely. | PrepareRead/PrepareWrite are passed a fixed size of 4 for all access widths, so byte and halfword accesses check a 4-byte range and trip memchecks that were not hit.
- Core/MIPS/x86/CompVFPU.cpp (2013-02-16): Comp_VDot uses DestRegOverlaps, which now allows dregs[0] == sregs[0], and then maps dregs with MAP_NOINIT so the source value is not loaded; the final MOVSS also copies XMM0 instead of tempxreg. | Comp_VDot now allows dregs[0] to equal sregs[0] (DestRegOverlaps ignores index di) but maps the destination with MAP_NOINIT, so the source value is never loaded and the dot product reads garbage.
- Core/HLE/HLE.cpp (2012-11-04): ResolveSyscall patches the import stub with JAL instead of J, so the callee returns into the stub instead of to the original caller. | ResolveSyscall patches the import stub with JAL instead of J, overwriting ra so the called module function returns into the stub instead of the caller.
- GPU/GLES/DepalettizeShader.cpp (2014-03-30): The new 5551 alpha multiplier 1/128 maps a 1-bit alpha index to palette entry 2 instead of 1 in the 256-wide CLUT texture. | The newly added 5551 alpha multiplier 1/128 maps a 1-bit alpha to palette index 2 instead of 1 (the fix uses 1/256); the case labels 4/8 it also fixes were already wrong before.
- GPU/GLES/TextureCache.cpp (2016-05-01): ApplyTexture computes the new hash into a local fullhash that is never stored, so entry->fullhash is no longer updated after this change removed the assignment from SetTexture. | ApplyTexture computes the full hash into an unused local instead of entry->fullhash (the old entry->fullhash assignment was removed), so rebuilt textures keep a stale hash.
- Core/HLE/sceDisplay.cpp (2014-06-01): hleLagSync uses scale = iFpsLimit / 60 instead of 60 / iFpsLimit, so a faster alternate speed makes each sync wait longer. | hleLagSync scales the 1 ms wait by iFpsLimit / 60 instead of 60 / iFpsLimit, so alternate speeds sync in the wrong direction.
- Core/HLE/sceAudioRouting.cpp (2015-03-08): NID 0x28235C56 is registered as sceAudioRoutingSetVolumeMode taking an argument, but it is sceAudioRoutingGetVolumeMode, so a game's get call overwrites the mode with garbage. | NID 0x28235C56 (sceAudioRoutingGetVolumeMode) is bound to sceAudioRoutingSetVolumeMode with an int argument, so games calling the getter run the setter with a garbage argument.
- Core/Reporting.h (2014-02-17): PointerWrap is forward-declared as struct while it is defined as a class, which breaks the MSVC build (different name mangling). | PointerWrap is forward-declared as struct while it is defined as a class, which breaks the MSVC build (class-key mismatch changes name mangling).
- GPU/GLES/Framebuffer.cpp (2014-01-01): ClearBuffer calls glClearDepth, which does not exist in OpenGL ES 2, breaking the GLES builds. | ClearBuffer calls glClearDepth(1.0), which does not exist in OpenGL ES 2, breaking GLES builds; the fix uses glClearDepthf.
- ext/native/thin3d/thin3d_vulkan.cpp (2017-12-03): ~VKContext deletes the VulkanDeviceAllocator immediately although textures freed earlier have queued deletions that still use it, a use-after-free on shutdown. | ~VKContext deletes allocator_ immediately although freed texture memory has queued DispatchFree callbacks pointing at the allocator, causing a use-after-free when the delete queue runs on shutdown.
- Core/TextureReplacer.cpp (2021-10-21): The threaded load has no lifetime coordination: LimitedWaitable::Wait/WaitFor use the inverted predicate !triggered_ and never wait, and IsReady deletes the waitable while the task may still be in Notify or the texture may be destroyed under the task. | The new background ReplacedTextureTask holds a raw reference to the texture and its LimitedWaitable, and IsReady releases (deletes) the waitable as soon as triggered_ is seen while Notify may still hold its mutex (Wait predicates are also inverted), so destroying or releasing races with the loader thread and can crash.
- Core/HLE/sceKernelThread.cpp (2012-11-12): sceKernelCancelWakeupThread writes 'uid == __KernelGetCurThread()' (a comparison) instead of an assignment, so uid 0 is never resolved to the current thread. | sceKernelCancelWakeupThread uses uid == __KernelGetCurThread() (comparison) instead of assignment, so uid 0 is never mapped to the current thread.
- GPU/GPUState.cpp (2014-04-18): The legacy-savestate skip buffer l4 is declared float[3] but lightangle and lightspotCoef were float[4], so old savestates are read misaligned. | The legacy savestate reader uses float l4[3] for the old 4-float lightangle and lightspot arrays, misreading older savestates.
- Core/HLE/sceAtrac.cpp (2013-02-01): numSamples is computed as unsigned (bufferSize - decodePos) while decodePos advances past bufferSize, so it underflows to a huge value, gets clamped to the max, and the loop restart branch (numSamples == 0) never triggers. | decodePos advances by ATRAC_MAX_SAMPLES past bufferSize and the unsigned (bufferSize - decodePos) underflows, so numSamples never reaches 0 and looping never restarts.
- UWP/XAudioSoundStream.cpp (2025-06-17): A single audioBuffer_ is refilled and resubmitted while up to bufferCount earlier submissions of the same memory are still queued in XAudio2, which does not copy the data, causing audio glitches. | A single audioBuffer_ is refilled and resubmitted while XAudio2 still holds up to bufferCount queued references to it, corrupting queued audio (glitches).
- ext/native/ui/viewgroup.cpp (2015-12-22): The vertical branch tests measuredWidth_ < vert.size instead of measuredHeight_ < vert.size before growing measuredHeight_. | The vertical branch tests measuredWidth_ < vert.size instead of measuredHeight_ when deciding to grow the height.
- Core/ELF/ElfReader.h (2012-11-01): ElfReader's empty destructor never frees sectionOffsets and sectionAddrs, which LoadInto allocates with new[], so every loaded ELF leaks them (members are also left uninitialized). | The ElfReader destructor is empty although LoadInto allocates sectionOffsets and sectionAddrs with new[], leaking them (and members are left uninitialized).
- Common/Render/Text/draw_text_sdl.cpp (2025-10-13): AlphaToPremul4444 expects an 8-bit alpha value but is passed the full 32-bit SDL pixel, so it takes bits 4-7 of the color instead of the alpha and SDL text renders wrong. | AlphaToPremul4444 is passed the whole 32-bit RGBA pixel instead of its alpha byte (>> 24), so it takes bits 4-7 of the red channel and SDL text renders wrong.
- Core/HLE/sceAtrac.cpp (2012-12-23): sceAtracSetHalfwayBufferAndGetID is given a spurious leading atracID parameter (wrapped as WrapI_IUUU), so every real argument is read from the wrong register. | sceAtracSetHalfwayBufferAndGetID was given an extra atracID first parameter (WrapI_IUUU), shifting all real arguments (halfBuffer, readSize, halfBufferSize) by one.
- Core/System.cpp (2025-03-26): mipsr4k.Reset() was moved after CoreTiming::Init() and HLEInit(), so MIPSState::Init zeroes downcount (set to INITIAL_SLICE_LENGTH by CoreTiming::Init) and other CPU state those inits set up. | mipsr4k.Reset() was moved after CoreTiming::Init and HLEInit, so it wipes MIPS state they set up (for example downcount and the JIT).
- Core/PSPLoaders.cpp (2014-04-19): On Linux realpath strips the trailing slash, so path = rootNorm has no separator and DirectoryFileSystem builds paths as basePath + localpath, producing wrong host paths when mountRoot is used. | On Linux realpath strips the trailing slash, so path = rootNorm has no separator and DirectoryFileSystem builds wrong host paths when mountRoot is used.
- Common/UI/Root.cpp (2025-11-04): Root margins shift x/y by left/top but shrink w/h only by right/bottom, and the measure specs still use the unreduced size, so the root extends past the screen and buttons are cut off. | Root margins subtract only right/bottom from width/height after offsetting by left/top, and the root is measured at the full size, so content is shifted and cut off.
- Core/HW/SasAudio.cpp (2013-10-24): In the new SasVoice::ReadSamples PCM path, memset(output + size, 0, remaining) adds a byte count to an s16 pointer, leaving part of the buffer unzeroed garbage and possibly writing past resampleBuffer. | The refactored PCM path does memset(output + size, ...) with output an s16 pointer and size in bytes, zeroing the wrong region and writing past the buffer when a PCM voice wraps.
- android/jni/UIShader.cpp (2012-11-25): UIShader_Prepare enables blending and sets the blend func with raw glEnable/glBlendFunc, bypassing the glstate cache, so later glstate.blend/blendFunc.set calls can be skipped and game draws get the UI blend state. | The added raw glEnable(GL_BLEND) and glBlendFunc calls bypass the glstate cache, leaving the emulator's cached blend state out of sync with GL.
- Core/HLE/sceFont.cpp (2014-02-25): In sceFontFindOptimumFont any later font whose fields match (MATCH_GOOD) overwrites optimumFont, so the nearest-size font selected via nearestDist is lost. | FindOptimumFont marks the nearest-size candidate by setting q = MATCH_GOOD, but any later font that merely matches the style fields also overwrites optimumFont, so the nearest size is lost.
- gfx_es2/draw_text.h (2014-08-22): The header changed the TextDrawer constructor to TextDrawer(Thin3DContext*) (and made TextStringEntry Win32-only Thin3D) while the non-Win32 draw_text.cpp path still defined TextDrawer() and used GL handles, breaking the Linux/Android build. | TextStringEntry has a Thin3DTexture member only on Win32 while the shared draw_text code now uses texture, breaking Linux and Android builds.
- Windows/GEDebugger/TabVertices.cpp (2014-02-08): CtrlMatrixList::GetColumnText dereferences gpuDebug (gpuDebug->GetGState()) without checking it for null, so the matrix tab crashes when no GPU debug interface exists. | CtrlMatrixList::GetColumnText dereferences gpuDebug without a null check (GetRowCount checks it), crashing the matrix tab when no GPU debug interface exists.
