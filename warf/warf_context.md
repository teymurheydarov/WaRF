# WaRF Project Context — WaRF itself

## What this project does
WaRF (Weighted n-Agent Reliability Framework) is a Bayesian multi-agent code review
system. It runs multiple LLM agents with distinct review personas, applies SPRT
sequential stopping, and Bayesian-updates per-agent weights based on oracle feedback.

## Stack
- Python 3.10+; the core has no third-party dependencies (optional extras: `anthropic`,
  `sast`, `plots`, `mcp`)
- Model backends live in providers.py: the `claude` CLI (default when no API key is set),
  the Anthropic API, OpenAI-compatible endpoints (also Ollama). Which one answers can be
  set per agent.
- Output: terminal + sessions.jsonl log; HTML pages generated by plot_*.py scripts

## Key conventions
- All math (SPRT, Bayesian update, synthesis) lives in engine.py — keep it pure functions
- orchestrator.py drives the review loop and asks the providers for votes
- providers.py owns every call to a model, including the subprocess call to the claude CLI
- cli.py is the user-facing entry point; state.py owns weight persistence; paths.py decides
  where profiles and the session log live
- No framework, no ORM, no async — keep it simple

## What to flag
- Any change that could corrupt sessions.jsonl (the oracle training data)
- Subprocess injection risks in ClaudeCLIProvider.complete() in providers.py (user-controlled
  input passed to the CLI)
- Weight persistence bugs — alpha/beta must stay at or above the prior of 1
- SPRT boundary logic changes — A and B derive from the error tolerances alpha and beta
  in engine.py; don't touch without justification

## Known false positives to ignore
- The subprocess.run() call in providers.py (ClaudeCLIProvider) is intentional: it calls the
  claude CLI
- _NEUTRAL_CWD in providers.py is set to the home directory intentionally (prevents
  CLAUDE.md injection)
